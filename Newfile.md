# What I have understood on github basics:

I got to understand the purpose of git which is that it is used to track changes to ones code. It provides version control ensurring that you can go back to previous versions of your code if you need to. 

Github is an online platform where ones git history is stored. Since your code is stored online you can **clone**(get a local copy) it from the repository under which it is stored on any device as long as you log into github and do so.

Once you clone a repository onto your local machine and make changes to the code, the code on you machine will be ahead of the online version in terms of **commits**. You can update the online version by **pushing** the commits from your local machine to the online version of the code. (**commits** are snapshots of your code at given points)

Github is ideal for collaborations. Diffrent developers can be given access to a **repository**(project) and they can contribute to said repository in an oderly manner. The developers work in diffrent branches and merge their code once they deem it necessary to do so. They merge their code using **pull requests**. 

Developers use github as portfolios. They make their projects(**repositories**) public thus displaying their skills to not only fellow developers but also an entire community consissting of students, hobbyists, explorers e.t.c

Issues are used for task management. I am yet to fully understand how they work.
